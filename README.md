# Метаболический контур

Телеграм-агент для контроля веса. Диалог на естественном языке, вся арифметика —
детерминированный python, модель ни одного числа не считает и не выдумывает.

SQLite как единственный источник истины. Работает на слабом VPS. LLM подключается
любая по API.

---

## Порядок запуска на VPS

Пять шагов, строго в этом порядке.

**1. Установка**

```bash
./install.sh
```

Создаёт venv в каталоге проекта, ставит в него пакет, заводит пустой `.env`,
инициализирует базу и прогоняет самотесты. Идемпотентен. Только Debian.

**2. Секреты**

```bash
nano ~/.hermes/.env
```

Заполнить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USERS` и `GOOGLE_API_KEY`
(имя переменной берётся из `bot.providers` в `config.yaml`). Бот по умолчанию
отказывает **всем** — без `TELEGRAM_ALLOWED_USERS` он не ответит никому.

**3. Автозапуск**

```bash
systemctl --user enable --now health-agent.service
```

Предварительно один раз от root: `loginctl enable-linger <username>`. Без этого
systemd убьёт бота при выходе из ssh.

**4. Регистрация**

Написать боту в телеграм. Профиль вводится диалогом: рост, дата рождения, пол,
стартовый вес. Вехи задаёт пользователь, своих целевых чисел у системы нет.

**5. Расписание**

Только теперь. Один systemd-таймер `health-dispatch` рассылает задачи по
локальному времени каждого человека, плюс ночной бэкап — `DEPLOY.md`, раздел
«Задачи расписания».

Раньше нельзя: на пустой базе большинство скриптов завершается ошибкой каждую
ночь.

## Импорт истории

Разово, после регистрации:

```bash
python migrate.py --user 1 --scale <файл.xlsx> --tcx <каталог> --anthro <файл.csv>
```

Идемпотентен: повторный прогон добавляет ноль строк.

## Раскладка

```
health_core/     доменная логика, о боте не знает ничего
  db models config energy nutrition guards report export
  ingest/        scale tcx anthro
bot/             собственный цикл агента: registry, llm, history, knowledge, main (aiogram)
plugin/          24 инструмента + схемы, register(ctx) — контракт не поменялся
scripts/         6 cron-скриптов (--no-agent) + notify.py, который их запускает и шлёт вывод в телеграм
admin/           веб-панель: авторизация, страницы, /knowledge — загрузка файлов базы знаний
Core/            персона, system_promt.md — бот читает файл с диска напрямую
Knowledge/       протокол, препараты, домены — инструмент knowledge(topic) в bot/knowledge.py
migrate.py       разовый импорт истории
test_e2e.py      сквозной тест доменной логики, 10 стадий
test_bot.py      сквозной тест цикла агента без сети, 10 сценариев
Docs/bot_design.md  контракт перехода с Hermes на bot/: архитектура и мотивация
SPEC.md          архитектура, 17 разделов
DEPLOY.md        подробный ранбук + раздел для Windows
```

Граница проходит по `plugin/tools.py`: `bot/registry.py` вызывает его
`register(ctx)` со своим `ctx`-шимом, ни `plugin/tools.py`, ни `health_core/`
при переходе с Hermes на aiogram не менялись (подробности — в
`Docs/bot_design.md`).

## Проверки

```bash
python test_e2e.py
```

Десять стадий на реальных данных: регистрация, веха, импорт 247 замеров и 55
тренировок, повторный импорт, запись еды и воды, гардрейлы, статус-бар, тренды,
экспорт, бэкап.

```bash
python test_bot.py
```

Десять сценариев цикла агента без сети и без телеграма: HTTP-слой `bot/llm.py`
подменяется заранее заданными ответами, история и диспетч работают как есть.
Проверяет то, что самотесты отдельных модулей не видят — что `registry`,
`llm`, `history` и `knowledge` соединяются друг с другом так, как договорено в
`Docs/bot_design.md`.

Модульные самотесты — у каждого модуля свой `__main__`:

```bash
python -m health_core.db
```

Так же для `energy`, `guards`, `ingest.scale`, `export`, `plugin.tools`,
`bot.registry`, `bot.llm`, `bot.history`, `bot.knowledge`.

На Windows консоль по умолчанию использует cp1251 и ломает кириллицу и эмодзи
в выводе самотестов. Перед `python -m ...` задайте кодировку:
`$env:PYTHONIOENCODING='utf-8'` (PowerShell) или `set PYTHONIOENCODING=utf-8`
(cmd).

## Состояние

Проверено на настоящих данных: импорт и его идемпотентность, калораж, гардрейлы,
экспорт, ротация бэкапов, все cron-скрипты. Офлайн, без сети и без телеграма:
контракт `ctx.register_tool()` и весь набор из 24 инструментов
(`python -m bot.registry`), цепочка фолбэка провайдеров и цикл вызова
инструментов на подменённом HTTP-слое (`python -m bot.llm`), обрезка истории
по числу сообщений и по символам (`python -m bot.history`), выдача базы знаний
с учётом режима admin/user (`python -m bot.knowledge`), и сборка всех четырёх
модулей вместе (`python test_bot.py`, десять сценариев).

**Не проверено:**

- реальный телеграм-поллинг с живым токеном (`aiogram.Dispatcher.start_polling`)
  — самотесты его не запускают;
- живой ответ провайдера LLM — `bot/llm.py` проверен только на подменённом
  HTTP-слое, запрос к `generativelanguage.googleapis.com` вживую не делался;
- cron на VPS — восемь задач существуют как строки для `crontab` (см.
  `DEPLOY.md`), но сам crontab на боевой машине не заводился;
- команда старта в `health-agent.service` — помечена в файле как непроверенная.

**Известные ограничения:**

- `llm_calls` никто не заполняет. Usage теперь приходит в ответе провайдера
  (`bot/llm.py::chat` получает его вместе с остальным телом ответа), но запись
  в таблицу пока не сделана — решение отложено до момента, когда учёт токенов
  реально понадобится (см. `Docs/bot_design.md`, раздел «Границы»).
- Дефицит под срок вехи считается только для метрики `weight_kg`. Для талии и
  FFMI перевода в килокалории спека не даёт.
- Недельное перераспределение — плоский множитель, схема в спеке не задана.
- Бэкап хранит 7 суточных копий. Политика наша, §13 её не описывает.

## Инвариант

Цель по калориям никогда не опускается ниже безопасного пола. Ни при каком
входе — включая недостижимый срок вехи, отрицательный расход на тренировке и
рефид. Если срок недостижим без пробоя границы, система удерживает границу и
говорит, что срок недостижим.

Пол считается не от BMR, а от того, сколько энергии способна отдать жировая
ткань: около 31 ккал в сутки с килограмма жира, с запасом 0.7 (`config.yaml`,
`policy.fat_supply_*`). Дефицит сверх этого потолка организм добирает из мышц —
ровно от этого пол и защищает. BMR жировую массу не видит вовсе и потому одинаково
неверен в обе стороны: переосторожен при большом запасе жира, слишком мягок у
сухого человека. Граница движется сама по мере похудения.

Снизу пол подпёрт макро-минимумом: в цель обязана помещаться собственная норма
белка и минимум жиров. Нет биоимпеданса — жировую массу оценивать нечем, и пол
возвращается к BMR.

Пороги живут в `config.yaml` и `user_targets`, а не в контексте разговора.
Уговорить бота поднять порог нельзя.
