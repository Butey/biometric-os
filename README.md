# Метаболический контур

Персональный Telegram health-бот: aiogram, SQLite и детерминированные расчёты Python.
Внешний агентный шлюз не требуется.

## Структура

```text
.env.example          шаблон настроек без ключей
.env                  локальные секреты (не в Git)
health.db             рабочая SQLite (не в Git)
config.yaml           политика расчётов и провайдеры LLM
health_core/          доменная логика, БД, импорт и экспорт
bot/                  Telegram, LLM, история и реестр инструментов
plugin/               собственные схемы и обработчики инструментов
admin/                административная панель
Core/, Knowledge/     инструкции и справочные материалы
scripts/              cron, установка релизов и обслуживание
scripts/diagnostics/  ручные сетевые пробы (не часть запуска)
systemd/              все службы и таймеры
admin/nginx-health-admin.conf  пример nginx
Docs/                 актуальная документация и ADR
Docs/archive/         исторические спецификации, исследования, материалы Hermes
Metrics/, Nutrition/  исходные пользовательские данные (не в Git)
backups/, export/      резервные копии и выгрузки (не в Git)
history_archive/      JSON-снимки переписки перед сжатием (не в Git)
```

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install -e .
[ -f .env ] || cp .env.example .env
chmod 600 .env
# Заполните ключи и Telegram ID в .env
python -m bot.main
```

Панель: `python -m admin.server`. Тесты: `python test_bot.py`, `python test_e2e.py`.
E2E использует локальные исходные файлы Metrics. Все тесты работают с временными БД.

На Linux установку и перенос старых данных выполняет `./install.sh /путь/к/проекту`.
Перед переносом остановите сервисы; существующие `.env` и `health.db` не перезаписываются.
Установщик сохраняет исходники старого расположения для отката. Hermes упоминается
только в процедуре однократного переноса и исторических материалах.

## Данные, история и экспорт

SQLite — источник фактов; расчёты выполняет `health_core/`, модель выбирает
инструменты и объясняет результат. Утренний отчёт показывает пропуски за нужную
дату: старый замер не становится сегодняшним. Последние известные значения
могут использоваться для расчётов и статуса с указанием их времени.
Оценка плато использует сопоставимые наблюдения; причины изменения веса
остаются гипотезами, если их не подтверждают данные. FFM — безжировая масса,
включающая воду и другие ткани; её изменение не равно потере мышц.

- `.env` и `health.db` по умолчанию находятся в корне проекта, независимо от
  текущего каталога запуска. `HEALTH_DB` может задать другой путь; относительный
  путь считается от проекта. Переменные процесса имеют приоритет над `.env`.
- Сохранённая переписка находится в таблице `chat_history`. Перед суммаризацией
  и очисткой создаётся JSON-снимок всех доступных записей пользователя,
  включая сохранённые вызовы инструментов и их ответы.
- Архивы: `history_archive/<telegram_id>/<sha256>.json` рядом с выбранной БД.
  Ошибка записи архива отменяет удаление истории. Ранее удалённые сообщения
  снимки восстановить не могут.
- `/export` отправляет архив собственных данных в личный Telegram-чат.
  История перед суммаризацией архивируется отдельно на диске.
- `.env`, БД, исходные пользовательские данные и архивы исключены из Git.
  Установочный архив `scripts/build_release.py` содержит снимок БД и предназначен
  для частного переноса; реальные `.env` в него не включаются.
