# Результаты системного аудита и ТЗ для разработчиков / LLM

В этой папке (`/opt/webapps/health_agent_system/audit_results/`) собрана полная аналитическая и техническая документация по устранению скрытых дефектов в логике расчёта калоража, энергобаланса и гардов проекта Health Agent System.

---

## Структура файлов

1. **[`01_system_calculation_audit.md`](./01_system_calculation_audit.md)**
   * **Главный технический документ:** полный перечень 10 скрытых дефектов системы с точными ссылками на строки кода, формулами, математическим анализом и пошаговыми инструкциями по исправлению.
   * Охватывает: сброс адаптивного TDEE в `None` (скачок на +626 ккал), ложные алерты `BINGE_RISK` и `BMR_FLOOR`, ошибки прогнозирования в `forecast.py`, сглаживание веса, зависание вех.

2. **[`02_workout_calories_deep_dive.md`](./02_workout_calories_deep_dive.md)**
   * **Глубокий физиологический и архитектурный анализ проблемы «Eat-Back Calories»:** почему калории тренировок нельзя прибавлять к норме питания.
   * Включает научное обоснование (модель ограниченных энергозатрат Германа Понтцера, двойной счёт в адаптивном TDEE, погрешности оптических датчиков) и архитектурную схему отвязки тренировок от нормы еды.

3. **[`03_refeed_refactor_summary.md`](./03_refeed_refactor_summary.md)**
   * **Отчёт о выполненном рефакторинге системы рефидов:** исключение рефидов из расчета TDEE, миграция схемы БД до v28 (колонка `reason`), разовые 4-дневные рефиды по показаниям вместо 14-дневных циклов MATADOR, утренние нотификации за 2 дня и в день рефида.

---

## Рекомендуемый порядок работы для следующей LLM:
1. Ознакомиться с `02_workout_calories_deep_dive.md` для понимания концепции разделения тренировок и питания.
2. Взять в работу дефекты 1, 2 и 3 из `01_system_calculation_audit.md` (критические ошибки, непосредственно завышающие калораж и сдвигающие прогноз вех).
3. Последовательно реализовать исправления гардов (дефекты 4, 5, 6, 10).
4. Прогнать тесты: `.venv/bin/python3 -m pytest test_bot.py -q`.
