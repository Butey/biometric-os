## 1. Резюме и архитектурные ограничения (1 vCPU / 1 GB RAM)

На сервере с 1 GB RAM бюджет памяти предельно жесткий:
* **Базовый ОС Debian Minimal:** ~150 MB.
* **Hermes Agent Gateway / Python Daemon:** ~250–350 MB.
* **Резерв под дисковый кэш, SQLite WAL и буфер Telegram:** ~300 MB.
* **Доступно под внешние задачи:** **не более 200–300 MB RAM** без ухода в своп.
* **Уход в своп на 1 vCPU:** означает полную блокировку дискового I/O, скачок CPU iowait до 90–100%, тайм-ауты в Telegram боте и неизбежное срабатывание **Linux Out-Of-Memory (OOM) Killer**, который принудительно завершит процесс ассистента.

**Главный архитектурный вывод исследования:**  
На данном сервере **категорически запрещено запускать локальные тяжелые нейросетевые модели** (локальный OCR, Vision Transformers, эмбеддинги, локальные STT). Любые интеграции должны строиться по принципу:
1. **Легковесные асинхронные HTTP-клиенты (REST API / Webhooks) на Python** (<15–30 MB RAM).
2. **Векторный парсинг цифровых документов (PyMuPDF)** (<25 MB RAM).
3. **Делегирование тяжелого OCR/Vision внешним облачным мультимодальным LLM** (0 MB RAM, $0.001 за запрос).

### Детальный разбор лидеров

#### 1. Open Food Facts (OFF)
* **SDK:** `openfoodfacts` (Python) или прямой асинхронный вызов `https://world.openfoodfacts.org/api/v2/product/{barcode}.json`.
* **Формат данных:** JSON. Поля: `product_name_ru`, `nutriments.proteins_100g`, `nutriments.fiber_100g`, `nutriments.carbohydrates_100g`, `nutriments.fat_100g`, `nova_group` (1–4), `ingredients_text_ru`.
* **Плюсы для тирзепатида:** Содержит готовый индекс ультра-обработки **NOVA** (помогает ассистенту предупреждать пользователя о junk-food), граммовки пищевых волокон (клетчатки) и сахаров.
* **Нагрузка на VPS:** 0 MB постоянной памяти (вызов занимает 50–150 мс через `httpx.AsyncClient`).

#### 2. USDA FoodData Central (FDC)
* **Формат:** REST JSON (`https://api.nal.usda.gov/fdc/v1/foods/search`).
* **Плюсы:** Исчерпывающий аминокислотный состав (лейцин, валин, изолейцин) и микроэлементы (магний, калий, натрий). Когда пользователь пишет «съел 200г вареной индейки и 150г гречки», поиск в базе брендов не нужен — USDA дает лабораторно выверенную пищевую плотность.

### Рекомендованная стратегия интеграции питания:
1. **Штрих-код (EAN-13/UPC):** Запрос в **Open Food Facts API**. Если найден — берем БЖУ, клетчатку, NOVA-класс.
2. **Текстовое описание блюда:** Передается текущей LLM ассистента. LLM декомпозирует блюдо на ингредиенты и граммовки, сверяясь с локальным кэшем базовых продуктов (на базе среза USDA FDC).

* **Архитектура сна:** детекция бессонницы или фрагментации сна при титрации дозы.

### Детали реализации для проекта:

1. **Withings:** Самый мощный инструмент контроля состава тела. При настройке подписки на `notify/subscribe` сервер получает вебхук в момент взвешивания. Обработчик на Python считывает `weight_kg`, `muscle_mass_kg`, `fat_pct` и сразу валидирует недельный тренд дефицита.
2. **Apple HealthKit без сторонних серверов:** 
   * Создается стандартная команда **Apple Shortcuts**: триггер «По будильнику / В 08:00 утра» -> действие «Найти образцы здоровья за вчера» -> «Получить содержимое URL: POST https://agent.yourdomain.com/api/healthkit/ingest».
   * Нагрузка на сервер: микросекундная обработка JSON-пакета размером 2 КБ.
3. **Парсинг выгрузок XML (`export.xml`) — Внимание на 1GB RAM:**
   * Полный экспорт Apple Health весит 500 МБ – 2 ГБ в распакованном виде.
   * `xml.dom.minidom` или `BeautifulSoup` загружают дерево в RAM и требуют **в 4–6 раз больше памяти, чем размер файла** -> вызовут гарантированный краш VPS.
   * Если необходим импорт исторического архива — использовать **только потоковый `xml.etree.ElementTree.iterparse`** с обязательным вызовом `elem.clear()` на каждом узле:
     ```python
     for event, elem in ET.iterparse(xml_file, events=('end',)):
         if elem.tag == 'Record':
             # сохранение в SQLite
             elem.clear()
     ```

## 4. Интеграция с глюкометрами и CGM (Continuous Glucose Monitoring)

### Клиническая ценность при терапии тирзепатидом:
Тирзепатид — двойной агонист GIP/GLP-1 рецепторов. Он увеличивает первую и вторую фазы секреции инсулина глюкозозависимым образом, снижает продукцию глюкагона печенью и замедляет опорожнение желудка.
* **Цели трекинга:**
  1. Оценка **Time-in-Range (TIR 3.9–7.8 ммоль/л)**.
  2. Контроль **вариабельности гликемии ($CV < 36\%$)** — стабильный сахар без «американских горок» устраняет приступы компульсивного голода.
  3. Детекция скрытых реактивных гипогликемий при интенсивных силовых нагрузках на глубоком дефиците калорий.

### Детальное обоснование:

#### 1. Почему PaddleOCR, Nougat и Unstructured убьют сервер:
* Установка `paddlepaddle` или `torch` на Debian 1 vCPU требует скачивания тяжелых wheel-файлов (>400–800 МБ).
* При вызове `from paddleocr import PaddleOCR; ocr = PaddleOCR(...)` в память аллоцируются веса моделей детекции (DBNet), классификатора ориентации и распознавания (SVTR/CRNN).
* На сервере с 1 GB RAM, где уже работают ядро Linux и демон ассистента (~450 MB занято суммарно), запуск локальной нейросети вызывает нехватку физической памяти. Система начнет сбрасывать страницы в 2 GB swap. На медленном виртуальном диске 1 vCPU это приводит к **I/O Thrashing** (зависание всей системы на 1–2 минуты) и немедленной отправке сигнала `SIGKILL` процессу ассистента от ядра Linux.

#### 2. Проблема Tesseract на бланках анализов:
* Tesseract помещается в память (требует ~80 MB RAM), но он не понимает контекст и семантическую структуру сложных медицинских таблиц. 
* На бланках российских лабораторий (Инвитро, Гемотест, Хеликс) таблицы содержат 4–6 колонок: *Исследование*, *Результат*, *Единицы измерения*, *Референсные значения*, *Комментарий*. Tesseract часто считывает текст горизонтальными полосами поперек колонок, объединяя показатели разных строк. Восстановление такой структуры регулярными выражениями порождает критические медицинские ошибки.

### Эталонная продакшн-архитектура для 1 GB VPS:

Реализуется **гибридный двухконтурный пайплайн**:

```
Пользователь прислал документ в Telegram
                 │
      ┌──────────┴──────────┐
      ▼                     ▼
[Файл: PDF]            [Фото / Скан / Скриншот]
      │                     │
      ▼                     ▼
Проверка через PyMuPDF   Отправка напрямую в Vision LLM API
is_text_pdf = len(fitz.get_text()) > 100
      │                     │
  ┌───┴───┐                 │
 ДА      НЕТ                │
  │       └─────────────────┤
  ▼                         ▼
Мгновенное извлечение   Cloud Vision (GPT-4o-mini / Claude-3-5 / Gemini Flash)
текста (15 MB RAM, 30мс) (Structured JSON Output по Pydantic схеме)
  │                         │
  └───────────┬─────────────┘
              ▼
Нормализация единиц (ммоль/л, нг/мл) 
  и расчет клинических индексов в health_core:
  * HOMA-IR = (Глюкоза * Инсулин) / 22.5
  * TyG = ln(Триглицериды * Глюкоза / 2)
  * eGFR (CKD-EPI 2021)
  * Lipid Ratios (Triglycerides / HDL)
```

**Экономика и ресурсы решения:**
* Нагрузка на RAM VPS: **до 25 MB**.
* Нагрузка на CPU: **минимальная** (асинхронное ожидание ответа API).
* Стоимость: распознавание 1 бланка через `gpt-4o-mini` или `gemini-1.5-flash` стоит **$0.001 – $0.002** (доли копейки), что в сотни раз дешевле аренды более мощного VPS (для PaddleOCR потребовался бы сервер минимум 4 GB RAM, стоящий в 3–4 раза дороже).

## 6. Существующие MCP (Model Context Protocol) серверы

### Оценка архитектуры MCP в контексте 1 GB RAM VPS:

В документации Hermes Agent (`Docs/toolsets.md`, `Docs/hermes_ref/config.md`) предусмотрена секция `mcp_servers:`:
```yaml
mcp_servers:
  oura:
    command: python3
    args: ["-m", "oura_mcp_server"]
```
**Важнейшее предостережение по памяти:**
* Каждый сервер MCP на базе Node.js (`command: npx ...`) запускает отдельный рантайм Node.js v22 с V8 engine, потребляющий **от 60 до 100 MB RAM на каждый экземпляр**. Запуск 3–4 таких серверов отнимет 300–400 MB RAM и спровоцирует OOM.
* **Рекомендация:**
  1. Для максимальной экономии памяти в 1 GB VPS интеграции с Oura, Withings, Dexcom и Open Food Facts эффективнее реализовывать как **внутренние Python-модули `health_core`** (они работают в едином процессе демона Hermes и потребляют всего ~5–10 MB RAM суммарно на все клиенты).
  2. Если использовать внешние MCP — выбирать исключительно легковесные реализации на **Python FastMCP** с запуском через единое виртуальное окружение `.venv` без запуска Node.js.

## 7. Итоговая рекомендованная матрица интеграций

| Категория | Выбранное решение | Транспорт / Протокол | Нагрузка на RAM | Стоимость / Лицензия |
|---|---|---|---|---|
| **Штрих-коды и бренды РФ/СНГ** | **Open Food Facts API** | Async HTTP REST v2 (`httpx`) | <5 MB | Бесплатно (ODbL) |
| **Базовые/цельные продукты** | **USDA FoodData Central** | Async HTTP REST (`api.data.gov`) | <5 MB | Бесплатно (Public Domain) |
| **Умные весы (состав тела, LBM)** | **Withings API** | Webhooks (Inbound POST на сервер) | <2 MB | Бесплатно (OAuth 2.0) |
| **Трекинг сна и восстановления** | **Oura API v2** | REST API v2 через Personal Token | <2 MB | Бесплатно для личного использования |
| **Фитнес / Пульс / Активность** | **Apple Shortcuts Webhook** (iOS) или **GarminConnect** | HTTP POST JSON раз в день | <2 MB | Бесплатно (Native iOS / MIT) |
| **Гликемия и CGM** | **Nightscout API** или **pydexcom** | Async REST poll (раз в 5–15 мин) | <5 MB | Бесплатно (MIT / AGPL) |
| **Цифровые PDF анализов** | **PyMuPDF (`fitz`)** | Векторный C-парсер текста | 15 MB | Бесплатно (AGPL) |
| **Фото бланков, чеков, тарелок** | **Cloud Vision LLM API** (внешний) | Base64 Image HTTPS запрос к LLM | 0 MB (на VPS) | ~$0.001 – $0.002 за изображение |
| **Инструменты агента** | **health_core plugins** (в процессе) | In-process Python tool calls | 0 MB overhead | MIT |

Данная конфигурация гарантирует потребление оперативной памяти сервером в пределах **450–600 MB RAM из 1024 MB**, обеспечивая 100% стабильность работы ассистента без риска сбоев OOM Killer и задержек в Telegram.
