# Провайдеры LLM в bot/

Заменяет `HERMES-CONFIG.md`: то, что раньше настраивалось командами Hermes
(`hermes model`, `hermes fallback`, `hermes setup`), теперь — обычный YAML в
`config.yaml`, раздел `bot.providers`, и код в `bot/llm.py`. Своих команд для
этого не заводили — их незачем писать поверх плоского списка в конфиге.

## Секреты

Ключи не хранятся в `config.yaml` — только имя переменной окружения
(`api_key_env`). Значения — в `~/.hermes/.env`, тот же файл, что и у
`admin/` (`admin/auth.py` читает пароль панели оттуда же). Второго места для
секретов в проекте нет.

```
GOOGLE_API_KEY=AI...
```

`chmod 600 ~/.hermes/.env` — иначе ключи читает любой пользователь на машине.
`install.sh` выставляет права сам при первом создании файла.

## Выбор модели и фолбэк

`bot.providers` — список в `config.yaml`, порядок = приоритет:

```yaml
bot:
  providers:
    - base_url: https://generativelanguage.googleapis.com/v1beta/openai
      api_key_env: GOOGLE_API_KEY
      model: gemini-3.7-flash
    - base_url: https://generativelanguage.googleapis.com/v1beta/openai
      api_key_env: GOOGLE_API_KEY
      model: gemini-3.5-flash-lite
```

`bot/llm.py::chat` идёт по списку по порядку и переходит к следующему
провайдеру, если: переменная из `api_key_env` не задана в окружении, сетевая
ошибка или таймаут, HTTP 429, любой 5xx, или ответ не разобрать (нет
`choices[0].message`). Упали все — `RuntimeError` с перечислением причины по
каждому. Ретраев внутри одного провайдера нет: цепочка фолбэка дешевле и
надёжнее одного провайдера с повторными попытками.

Цепочка обязательна на free tier: лимит выбивается быстро, и без второго
элемента в списке бот в этот момент просто замолкает — выглядит это как
поломка, а не как временная перегрузка.

`base_url`, оканчивающийся на `/openai` — OpenAI-совместимый эндпоинт Gemini.
`bot/llm.py` шлёт единственный HTTP-путь: `POST {base_url}/chat/completions` с
`Authorization: Bearer <ключ>`. Нативного адаптера Gemini, как у Hermes, в
проекте нет — второй путь в коде поддерживать незачем при одном HTTP-клиенте
на весь бот.

## Почему flash, а не pro

Гардрейлы, калораж, статус-бар и вехи считает python в `health_core/`. Модель
не принимает ни одного числового решения — она пересказывает то, что вернул
инструмент, и ведёт разговор. Платить за старшую модель здесь не за что. Если
модель начнёт путаться с вызовом инструментов — поднимать до `pro` явной
правкой `model:` в `config.yaml`.

## Проверка после правки

```bash
python -m bot.llm
```

Подменяет HTTP-слой (`bot/llm._post`) и проверяет цепочку фолбэка, обработку
429/5xx/битого JSON в `tool_calls.arguments` и предохранитель от зацикливания
на инструментах — без сети. Живой ответ провайдера этим не проверяется
(Windows: `PYTHONIOENCODING=utf-8` перед запуском, вывод самотеста на
кириллице — см. README.md).
